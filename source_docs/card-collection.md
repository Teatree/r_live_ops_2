# Card Collection (packs, albums, star chests)

**Status:** wired 2026-08-03 (D19). Pack *gains* are simulated in the main engine; pack *opening*
is a separate downstream simulator. **Every pack reward ladder cell currently ships at 0** — the
values are authored by hand (see "What you have to fill in" below).

Sheets: `PackConfig` (config, generated by `builders/_build_packconfig.py`), `AlbumConfig` (the
72-card catalog), `SimOutput` (inputs + output, generated by `builders/_build_simoutput.py`),
`CardPoolConfig` (a scratch/test sheet — **not read by the engine**).
Deleted 2026-08-03: `EcoPackGains`, `PlayerBehavior`.

---

## 1. The two halves

| | where | what it answers |
|---|---|---|
| **Pack gains** | `EcoGainsSim_v4.gs` (`packLane_`), all four views | how many packs of each tier does a segment earn over the 33-day window, and from which sources |
| **Pack opening** | `CardOpenings.gs` (menu ▸ Simulate card pack openings) | given that flow, what cards does a player end up with — sets completed, albums finished, stars banked, chests bought |

The seam between them is `dailyPacksFor_(seg, payer, ctx)` in `EcoGainsSim_Daily.gs`, which returns
a 33×6 per-day grid broken down by source. The card sim reads that and nothing else about the
calendar — so the two views can never disagree.

## 2. Resources

Six tiers, appended as resources 14–19 (append-only rule):
`1-star Pack`, `2-star Pack`, `3-star Pack`, `4-star Pack`, `5-star Pack`, `6-star Pack`.

On the **config sheets** the same columns are spelled `1-star Dly` … `6-star Dly` (they have
existed on every ladder all along). `RES_MAP` translates. Nothing else was needed to make
`rewCols_`/`rewRow_`, `readLadder_`, the saga node reader and the PBP ladder readers see them.

## 3. How pack gains are priced

See `SIMULATION_METHODOLOGY.md` §6.12 for the full treatment. Short version:

```
packs[res] = E_v2[res] × participation_rate × Σ_instances reach(inst)      (cal_new only, no D)
```

Packs have **no measured anchor** (`data_gains` has no pack rows), so the usual
`measured × R × D × T` is identically 0 and the pack columns are **simulated-side only**: CURRENT
reads 0 and DIFF equals the simulated value. `E_v2` is the same expected ladder payout the R ratio
is built from, so packs are priced by exactly the machinery that prices coins on the same row.

Sources that pay packs: every simulated source with a config sheet, **plus** the carried
`Team Event` and `Flock Flurry` (pack overlay only — their other 13 resources stay measured).
Zero by construction: `Team Race`, `Ads`, `IAPs`, `Core`, `Saga`, `Daily Gift`, and the `A. 0`
appendix.

## 5. Pack opening model

**Pool.** The `PackConfig` SNAP POOL is the authoritative pool (1★ 281, 2★ 215, 3★ 143, 4★ 112,
5★ 66, Gold 0). Those copies are spread evenly across the `AlbumConfig` cards of each rarity
(remainder to the lowest indices). The sheet shows an `Initial Probability` column computed by
formula off the quantities — a readout, never a typed input.

**Draw.** Count-proportional, **without replacement**: `weight = copies × chapterMult`. Rarity is a
property of the pool and drifts as it depletes. The pool is rebuilt fresh only when an album
completes.

> **Removed 2026-08-03:** the per-pack `PACK RARITY PROBABILITIES` grid. It multiplied the pool
> counts (`rarityWeight × poolCount × chapterMult`), so rarity was applied twice — the clash that
> triggered this rework. Also dropped: `CardPoolConfig`'s per-card `Weight` column, for the same
> reason.

**What still differentiates a pack tier:** `Cards/Open` (2/3/4/5/6/7) and the pity table. Nothing
else — a 6-star pack and a 1-star pack draw from an identical distribution.

**Pity — two independent mechanisms:**
1. *Rarity pity* (`PACK PITY CONFIG`, implemented 2026-08-03; the table existed but was never
   read). `PityProbabilities` is indexed by the number of **consecutive misses of the target
   rarity** — not by card slot. `[0, 0.8, 0.8, 1.0]` reads: no help at first; miss once and the
   next pull has an 80% chance of the target; miss again, another 80%; miss a third time and the
   next pull is **guaranteed**. Entries past the end reuse the last value.
   The counter **resets on any hit** (forced or natural) and **starts at 0 on every pack** — it
   does not carry between packs.
   Target = the highest rarity that **still has copies** when `PityForceHighestRarity` is TRUE
   (so the empty Gold tier falls back to 5★ instead of making the pity unsatisfiable); otherwise
   any rarity above the pool's most-stocked one.
2. *Dry-streak* (unchanged): after 3 consecutive packs with no new card, the last card of the next
   pack is forced to be an unowned type.

**Chests.** `STAR CHEST COSTS & REWARDS` (Bronze 250 → 1-star, Silver 500 → 4-star, Gold 1000 →
5-star) gated by the `CHEST PURCHASING` panel: no purchase below `Min Stars to Consider Buying`, 0%
probability before `Urgency Start Day`, ramping linearly to `End-of-Season Buy Probability` on the
final day. Missing parameters mean "never buy" (a loud zero beats silently reverting to the old
hardcoded greedy sweep).

**Albums.** 3 albums before the loop; albums 2 and 3 reuse the same 72-card catalog with a fresh
pool, and only the reward row differs. An album index past the last defined row reuses that row.
Set and album rewards are reported in the pack log's Note column — they are **not** fed back into
`EcoGainsSim`, because the card sim consumes the pack flow rather than contributing to the
25-category universe.

## 6. Player model

`SimOutput!B2` = segment (`0-9` … `100+`, `A. 0`), `D2` = payer (`NONPAYER`/`PAYER`) — the real
`data_seg_beh` keys. `G2` = seed (blank → generated and written back).

Attendance is the **deterministic expected** `p_day` (weekday/weekend active rate), so pack arrival
is an expectation, not a coin flip. Randomness is confined to the card draws and to the trailing
fractional pack (a seeded Bernoulli, so the granted pack count is unbiased — the pre-D19 code
always rounded that remainder up).

Season length = the engine's 33-day calendar window on `cal_new`. `PackConfig`'s old
`Season Duration (days)` input is retired.


### 6b. Stochastic mode (D24, 2026-09-01)

`SimOutput`/`Col_Cards_Daily` above is ONE player. **EcoGainsSim ▸ Simulate card cloud (all
segments)** runs N players (default 50, `Col_Cards_Totals!B2`; seed in `D2`) across all ten
segment × payer permutations and writes the distribution to `Col_Cards_Cloud` (six cumulative
series as p10/p25/p50/p75/p90/MEAN per day, plus a MEANS block for cross-segment charts) and
`Col_Cards_Totals` (totals, cadence, the feature's own economy payout, packs and cards per source).

Both entry points go through **one shared season core** (`runOneCardSeason_`), so they cannot
describe different games. `A. 0` is excluded — no `data_seg_beh` row, so nothing can price its
reach. Ranges on those sheets are **p10-p90 across players, not min-max**. See
SIMULATION_METHODOLOGY §6.14.

## 7. Open questions / flagged assumptions

0. **RESOLVED 2026-09-01 — chests were never bought.** The `CHEST PURCHASING` heading had been
   renamed on the sheet to `CHEST PURCHASING (SIM CONTROLS)` while `loadPackConfig_` matched it
   exactly, so the panel was never found and the run degraded to `minStars = Infinity`. Block labels
   now match by prefix at a word boundary. See D24a.
1. **RESOLVED (D21)** — pack ladder values are authored. But the D24 sweep found that **two
   authored reward blocks are currently unreachable**. Over 2000 simulated players (200 per
   permutation, seed 1):
   * **Not one completes an album.** Best case anywhere is 63 of 72 unique cards (100+ PAYER);
     medians run 22 (0-9 NONPAYER) to 53 (100+ PAYER). So ALBUM REWARDS never pay, and albums 2
     and 3 are unreachable in a 33-day season.
   * **Not one buys a star chest.** Max stars earned anywhere is 238 against a `Min Stars to
     Consider Buying` of 250 — and the cheapest chest (Bronze) also costs 250. The threshold sits
     ~5% above the best outcome the pack flow can produce, so the whole chest lane is inert.
   Both are real model outputs, not plumbing failures. Either the pack flow is short, or the album
   size / chest costs are set for a longer season than 33 days. **Open design question.**
2. **`PACK PITY CONFIG` semantics — RESOLVED 2026-08-03** (user): consecutive-miss counter, resets
   on a hit, per-pack (no carry-over), target = highest rarity with stock. Gated in
   `_mock_cards.js`. Remaining sub-question: `PityForceHighestRarity = FALSE` (the 5-star pack)
   currently targets "any rarity above the pool's most-stocked one" — a reasonable reading of
   "better than what the pack usually gives", but not something the sheet states.
3. **`reach × participation_rate`** both encode activity, so their product mildly under-counts
   packs for high-participation events.
4. **`Team Event` / `Team Race` have no `data_event_inst` rows** → their ladder is priced at a flat
   rank average (every rank equally likely), the crudest pricing in the model.
5. **Packs have no spend model** — they are gains-only and blank in every NET block, even though
   the card sim opens them. If pack *stock* ever matters, that is a new lane.
6. **RESOLVED** — Gold is stocked (SNAP POOL Qty 41 since workbook (14)) and is drawn: 72 of
   1265 draws in the neutral-fixture measurement, against 63 expected from its pool share.
7. **`CardPoolConfig`** is now unreferenced. Delete it, or keep it as a scratch sheet?

the ECO dump (where `PackConfig` is pre-D19 and `loadPackConfig_` throws on load).

so the harness tests the layout the engine expects even before the sheets are imported. **Remove
each entry once imported** — leaving one there makes the overlay replace the REAL sheet, and any
formulas added to it, with a builder artefact (this happened to `Col_Cards_Daily`).
