# Rainbow Maker sheets — the local "Player Reach Simulation" on `data_rm_pace`

Second version, 2026-10-30 (D79). It replaces the 2026-10-28 (D77) formula. The workbook of record,
LIVE_OPS_V3 (8), still runs the **original** `data_RM` formulas on all four sheets: neither version
was ever pasted. This one also covers the re-pull asked for in `PROMPT_ab_data_missing.md`.

The block sits at `AI1:AS13` of `RM_1st`, `RM_2nd`, `RM_1st_v2` and `RM_2nd_v2`. For the percentile in
`AJ2` and the payer type in `AJ3`, it shows the milestone each segment has **reached** at the end of
every event day. It also shows (new, row 13) the share of participants who finish the whole ladder.
It reads the event's own distribution from `data_rm_pace`: the cumulative matchables per participant
at the end of each instance date.

The cell-by-cell list for all four sheets is the **RM local sim** tab of
`display/Config_Proposals_v1.xlsx`, generated by `builders/_build_cfgprop.py` from the same functions
the formulas below come from.

## Paste

1. **`AI4` = `Config`, `AJ4` = `RM_1st`** on `RM_1st` and `RM_1st_v2`, **`RM_2nd`** on `RM_2nd` and
   `RM_2nd_v2`. This is a new input. It is ignored until `data_rm_pace` carries an `rm_config` column.
2. **`AJ6`**: the formula below. Copy it to `AL6`, `AN6`, `AP6`, `AR6`, then fill `AJ6:AR6` down to
   row 12. The segment comes from the column's own header (`0-9_ms` … `100_ms`).
3. **`AK6`**: the reward formula. Copy it to `AM6`, `AO6`, `AQ6`, `AS6`, then fill down to row 12. It
   now includes `ToF_Ticket` (column Z), which the old version left out.
4. **`AI13` = `Completes the whole RM`, `AJ13`**: the completion formula. Copy it to `AL13`, `AN13`,
   `AP13` and `AR13`, and format all five as %.
5. Replace the old `AL2` text ("…0.325%", from the pre-launch data) with a pointer to row 13.

`AI6:AI12` keep their formulas (`=IF(1<=$B$3,1,"")` … `=IF(7<=$B$3,7,"")`).

### AJ6 — milestones reached by the end of the day

```
=ARRAYFORMULA(IF($AI6="","",LET(seg,IF(SUBSTITUTE(AJ$5,"_ms","")="100","100+",SUBSTITUTE(AJ$5,"_ms","")),hdr,data_rm_pace!$1:$1,tbl,data_rm_pace!$A:$ZZ,col,LAMBDA(n,IFERROR(INDEX(tbl,0,MATCH(n,hdr,0)),"")),seg_c,col("segment"),pay_c,col("payer_flag"),len_c,col("instance_length_days"),day_c,col("instance_day"),res_c,col("resource"),cfg_c,col("rm_config"),ok0,(seg_c=seg)*(pay_c=$AJ$3)*(res_c="ALL"),ok,IF(SUM(ok0*(cfg_c=$AJ$4))>0,ok0*(cfg_c=$AJ$4),ok0),len_s,MAX(FILTER(len_c,ok)),dte,IF(AND($AI6>=$B$3,$B$3>=len_s-1),len_s,MIN($AI6,len_s)),hit,ok*(len_c=len_s)*(day_c=dte),q,LAMBDA(n,IFERROR(AVERAGE(FILTER(col(n),hit)),"")),p25,q("cum_matchables_p25"),p50,q("cum_matchables_p50"),p75,q("cum_matchables_p75"),avg,q("cum_matchables_mean"),p10x,q("cum_matchables_p10"),p90x,q("cum_matchables_p90"),top,MAX(p75,8*avg-2*(p25+p50+p75)),p90,IF(ISNUMBER(p90x),p90x,p75+0.6*(top-p75)),p10,IF(ISNUMBER(p10x),p10x,0.4*p25),mat,IFERROR(SWITCH($AJ$2,"Avg",avg,"p10",p10,"p25",p25,"p50",p50,"p75",p75,"p90",p90),0),COUNTIF($C$16:$C$45,"<="&mat))))
```

### AJ13 — share of participants past the last milestone by the last day

```
=ARRAYFORMULA(LET(seg,IF(SUBSTITUTE(AJ$5,"_ms","")="100","100+",SUBSTITUTE(AJ$5,"_ms","")),hdr,data_rm_pace!$1:$1,tbl,data_rm_pace!$A:$ZZ,col,LAMBDA(n,IFERROR(INDEX(tbl,0,MATCH(n,hdr,0)),"")),seg_c,col("segment"),pay_c,col("payer_flag"),len_c,col("instance_length_days"),day_c,col("instance_day"),res_c,col("resource"),cfg_c,col("rm_config"),ok0,(seg_c=seg)*(pay_c=$AJ$3)*(res_c="ALL"),ok,IF(SUM(ok0*(cfg_c=$AJ$4))>0,ok0*(cfg_c=$AJ$4),ok0),len_s,MAX(FILTER(len_c,ok)),dte,IF($B$3>=len_s-1,len_s,MIN($B$3,len_s)),hit,ok*(len_c=len_s)*(day_c=dte),q,LAMBDA(n,IFERROR(AVERAGE(FILTER(col(n),hit)),"")),p25,q("cum_matchables_p25"),p50,q("cum_matchables_p50"),p75,q("cum_matchables_p75"),avg,q("cum_matchables_mean"),top,MAX(p75,8*avg-2*(p25+p50+p75)),x,MAX($C$16:$C$45),u,IFS(x<=0,0,x<=p25,0.25*x/MAX(p25,1E-9),x<=p50,0.25+0.25*(x-p25)/MAX(p50-p25,1E-9),x<=p75,0.5+0.25*(x-p50)/MAX(p75-p50,1E-9),x<=top,0.75+0.25*(x-p75)/MAX(top-p75,1E-9),TRUE,1),1-u))
```

## What changed from the D77 version, and why

- **Every column is found by its header name** (`col("…")`), as before, so a re-pull with moved or
  extra columns needs no edit.
- **`rm_config`**: when the pull carries it (asked for in `PROMPT_ab_data_missing.md`), each sheet
  reads only its own ladder's rows (`AJ4`). Without it, every sheet reads the pooled rows, which is
  what the D77 version did.
- **Per-instance rows are averaged** (`AVERAGE(FILTER(…))`), where D77 took the first matching row.
  Today's pull is pooled (one row per day), so the result is identical. A per-instance pull is
  averaged over its instances.
- **`p10` and `p90`** are read directly when the pull carries `cum_matchables_p10` / `_p90`. Without
  them, p90 is derived as before: the tail runs from p75 to the point where the distribution's mean
  equals the measured mean, `8 x mean - 2 x (p25 + p50 + p75)`, and p90 is 60% of the way along it.
  p10 is 0.4 x p25, the straight line from no matchables to p25. `AJ2` therefore accepts `Avg`,
  `p10`, `p25`, `p50`, `p75` and `p90`.
- **The reward text includes `ToF_Ticket`** (column Z).
- **Row 13 is new**: the share past the last milestone on the last day. It is read off the same
  piecewise curve: p25, p50 and p75, then the tail.

## The rule — the same one the engine uses (D77)

- **Day d of the event** reads the measured event's date `d`. The **last day of an event as long as
  the measured one** reads the final date, which holds the closing hours. Today's pull covers
  5-date instances (the 4-day event plus its closing day), so `RM_1st` / `RM_2nd` (`B3` = 4) read
  dates 1, 2, 3 and 5. `RM_1st_v2` / `RM_2nd_v2` (`B3` = 2) read dates 1 and 2: "the first two days
  of the 4-day event".
- The count is milestones **reached**. The engine also applies a per-cell claim factor (claiming is
  manual: 5-18% of reached milestones are never claimed at the low segments). This view does not; it
  shows what a player at that percentile could have claimed.
- ⚠ The A/B calendar runs **4-day** Rainbow Makers, while `B3` on the two `_v2` sheets says 2. The
  engine takes the length from the calendar (D72), so `B3` only sets how many days this block shows.
  Set it to 4 on the `_v2` sheets if you want them to show the A/B shape.
